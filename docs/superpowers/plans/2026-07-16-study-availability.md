# Study Availability Foundation (PR 1 of session-booking milestone) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** the availability substrate for session booking — Paris-time helpers extracted to shared-functions, pure availability/date-expansion functions with exhaustive unit tests, and a `getTutorAvailability` callable returning sanitized per-date slot grids to approved families only.

**Architecture (from the milestone design — do not re-litigate):** request-confirm booking lands in later PRs; this PR ships NO booking writes. Availability = tutor's weekly grid (`schedules/{uid}.weekly: Record<DayOfWeek, boolean[96]>`, 15-min slots) ∧ per-date overrides ∧ holiday-period grid substitution (`holidayMode === 'different'`) minus confirmed-session padding blocks minus past/notice-window slots. Output is boolean grids ONLY — no reasons, no session info (privacy). Caller gate = the searchTutors/sendTutorContactRequest gate chain PLUS `callerFamilyId ∈ profiles.tutor.approvedFamilies` (availability is consent-gated like contact fields).

**Scaffold contract:** types in apps/study-functions/src/types/{session.ts,sessionInstance.ts,status.ts} and validation/session.ts are dormant-but-authoritative for later PRs — do NOT modify them in this PR; this PR only READS SessionDoc's shape for the defense-in-depth subtraction query.

**Templates to READ first:** apps/functions/src/scheduled/parisTime.ts (the DST-correct helpers — the two-pass offset correction in parisWallTimeToUtc embodies the #74 fix); packages/shared-core/src/{types/schedule.ts,utils/schedule.ts} (ScheduleDoc, DayOfWeek, timeToSlotIndex/slotIndexToTime/areSlotsAvailable); apps/study-web/src/hooks/useHolidays.ts (getCurrentSchoolYear derivation — reimplement server-side); apps/study-functions/src/contact/sendTutorContactRequest.ts (caller gate chain + HttpsError conventions); apps/study-functions/src/search/searchTutors.ts (approvedFamilies check); packages/shared-functions structure (copy-then-re-export convention); tests/integration/study-contact/* and tests/setup/seed.ts (integration + seed conventions — tutor2's schedules doc already exists in seed).

**Invariants:** apps/web and sit behavior untouched (parisTime extraction must leave sit imports working via re-export); no Firestore writes anywhere in this PR (reads only); no client-visible reasons in availability output; every date computation goes through parisTime helpers or pure date-string arithmetic (NEVER ms-epoch day-stepping — DST); zod validation for all callable input; integration tests against emulators; full suite baseline 362 passed / 52 files (+1 local-only smoke-seed if present — do not commit it).

## Task 2: Pure functions — computeDayAvailability + expandRecurringDates + getSchoolYearsInRange
- In `packages/study-core/src/utils/availability.ts` (new; study-core has no utils dir yet — create + export from index):
  - `computeDayAvailability({date, weeklySlots, override, holidayGrid, confirmedBlocks, paddingMin, nowParis, noticeHours}): boolean[96]` — base grid = holidayGrid ?? override-custom-slots ?? weeklySlots for that DayOfWeek; override type 'unavailable' zeroes the day; subtract each confirmedBlock ± padding slots (padding ONLY when block.location ∈ {'family_home','tutor_home'}); zero every slot whose wall-clock start < nowParis + noticeHours (only relevant for dates within the notice horizon).
  - `expandRecurringDates(slot: RecurringSlot, fromDate: string, weeks: number, endDate: string | undefined, schoolWeeksOnly: boolean, holidayPeriods: {startDate: string, endDate: string}[]): string[]` — date-STRING stepping (add 1 day via a Y-M-D increment helper, never epoch ms), first occurrence of slot.day on/after fromDate, weekly cadence, truncate past endDate, drop holiday-period dates when schoolWeeksOnly (boundary dates inclusive).
  - `getSchoolYearsInRange(startDate, endDate): string[]` — server-side port of useHolidays' school-year derivation ("2026-2027" keys; a range can span two).
- TDD unit tests (in study-core's test setup — check how sit-core/study-core run unit tests): weekly grid passthrough; unavailable override; custom override; holidayGrid substitution; padding applied for family_home/tutor_home and NOT for online/library; block at day edges (no negative/overflow slot indices); notice-window zeroing for today vs untouched tomorrow; **DST dates**: 2026-10-25 (fall-back) and 2027-03-28 (spring-forward) — expandRecurringDates around both must keep weekly cadence and identical wall-clock times; holiday boundary inclusive both ends; endDate truncation; school-year spanning (late-August window touching two docs).

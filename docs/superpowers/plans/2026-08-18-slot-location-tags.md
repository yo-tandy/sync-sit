**Design:**
1. **Storage** — CORRECTED DURING IMPLEMENTATION: the shape originally planned here, `weeklyLocations?: { [day]: (string[] | null)[] }`, is a directly-nested array, which Firestore forbids — it was rejected at T1 (see the T1 commit message). What shipped is a sparse map per day, `weeklyLocations?: { [day]: { [slotIdx: string]: LocationPref[] } }` alongside `weekly` on the schedule doc: same index space as the boolean grid; an absent key = "use profile defaults"; a non-empty array = the override for that half-hour. Absent entire field = legacy doc, all defaults (zero migration). Store only vocabulary values (LocationPref set); junk-tolerant readers (#175 lesson: typeof/array guards at every consumer — one bad element must never throw in a callable).
2. **Engine/read side** — `getTutorAvailability` returns, per bookable range, the EFFECTIVE location set (override if every covered cell shares one; ranges spanning differing overrides split into sub-ranges — implement in the availability util with unit tests; keep ComputeDayAvailability's boolean logic untouched, layer the location resolution beside it). searchTutors: NO CHANGES (owner-directed) — add a comment in the plan-adjacent code only if a reader would wonder.
3. **Trust boundary** — `bookSession` (and `proposeSession` for the family-home dimension) validates the requested location against the slot's EFFECTIVE set server-side (override ?? profile prefs) and rejects invalid-argument otherwise. The client constraint is UX only. Integration pins both directions (allowed by override; denied when the override excludes it even though profile prefs allow; legacy doc falls back to profile prefs; recurring sessions validate against their weekly cells).
4. **Editor UX** — in the SchedulePage day editor, each contiguous ACTIVE range gains an optional tag control (chip multi-select of the four categories, default "profile defaults" state). Keep the drag-to-toggle boolean flow untouched; tags attach to ranges and write per-cell arrays on save. Overrides/holiday grids: OUT OF SCOPE this PR (weekly only) — render a short helper note where relevant and record the follow-up in the report; the booking validation must treat override-days' cells as profile-default.
5. **i18n** en+fr for all new copy (tag control labels reuse the existing location labels where possible).
6. **Rules** — schedules doc: if the existing rule has shape constraints, extend minimally for `weeklyLocations` (list-of-lists is hard to validate in rules — bound what's boundable: field allowlist if hasOnly exists; note that element validation lives in the server-side readers per the #175 arrondissements precedent). If the rule is a bare owner-write with no field constraints, NO rules change — state so with evidence.
